# 채점 기준표 (rubric)

resume-critic의 rubric.md를 길드 프로필용으로 옮긴 사본입니다. `scripts/evaluate.mjs`가 평가할 때마다 이 파일을 그대로 읽어 AI에게 보냅니다.
고치면 다음 평가부터 반영됩니다. 단, 이미 평가된 프로필은 프로필 내용이 바뀌어야 다시 평가됩니다 (`evaluations/<handle>.json`을 지우면 강제 재평가).

대상: 길드 프로필(소개 문구, 제품 목록, GitHub 공개 지표)과 제품 페이지 스크린샷.
각 항목 0~20점 정수. 아래 20/15/10/5/0 사이 점수(예: 12)는 가까운 두 단계 사이로 판단합니다.
보이지 않는 것은 없는 것으로 봅니다. "열심히 했다"는 말이 아니라 **자료에서 확인되는 사실**로만 점수를 줍니다.
## 기술 깊이
- 20: 왜 그렇게 만들었는지와 측정까지 있다. 예: "Supabase RLS로 사용자별 데이터 분리, 캐시 도입 후 응답 1.8초→0.3초, 실패율 로그로 확인"
- 15: 실제 배포·인증·결제·DB 같은 어려운 부분을 직접 붙였고 설명이 구체적이다. 예: "Next.js + Stripe 결제, Vercel 배포, 웹훅으로 구독 상태 동기화"
- 10: 동작하는 앱이지만 기술 설명이 "무엇을 썼다" 수준이다. 예: "React, Firebase, OpenAI API 사용"
- 5: 기술 이름 나열뿐이거나, AI가 만들어 준 코드를 그대로 쓴 흔적만 있다. 예: "Cursor로 만든 투두앱"
- 0: 기술 관련 내용이 없다.

## 실제 성과
- 20: 사용자·매출·사용량 숫자가 있고 기간·출처가 분명하다. 예: "출시 3개월, 가입 2,300명, 주간 활성 410명 (GA 캡처 첨부)"
- 15: 숫자가 있지만 규모가 작거나 기간이 짧다. 예: "Product Hunt 하루 120 upvote, 첫 주 가입 300명"
- 10: 써 본 사람이 있다는 말은 있으나 숫자가 하나뿐이거나 모호하다. 예: "친구·동아리 30명이 사용"
- 5: 결과 없이 "만들었다"만 있다. 예: "AI 챗봇 웹사이트를 개발함"
- 0: 결과에 대한 내용이 전혀 없다.

## 차별성
- 20: 남이 쉽게 따라 못 하는 것이 있다. 예: "직접 모은 매장 메뉴 데이터 4만 건", "오픈소스 라이브러리 기여 머지", "해커톤 대상"
- 15: 흔한 주제지만 분명한 자기만의 각도가 있다. 예: "일반 할 일 앱이 아니라 교대근무 간호사용 일정 앱, 현직 간호사 5명 인터뷰 반영"
- 10: 기존 서비스와 비슷하고 차이가 작다. 예: "노션 같은 메모 앱에 AI 요약 버튼 추가"
- 5: 튜토리얼·클론 그대로다. 예: "유튜브 강의 따라 만든 넷플릭스 클론", "ChatGPT API 래퍼 챗봇"
- 0: 차별점을 찾을 수 없다.

## 증거·전달력
- 20: 누구나 바로 확인할 수 있다. 예: 실제 열리는 라이브 데모 링크 + 공개 GitHub + 30초 데모 영상/스크린샷, 문장이 짧고 숫자 중심
- 15: 라이브 데모나 GitHub 중 하나가 있고 설명이 명확하다.
- 10: 스크린샷만 있고 직접 써 볼 방법이 없다. 또는 링크는 있지만 설명이 길고 흩어져 있다.
- 5: 링크·화면이 없고 "열정", "다양한", "참여" 같은 모호한 말이 많다.
- 0: 확인할 증거가 하나도 없다.

## 상용가능성
- 20: 돈을 내는 고객이 있다. 예: "유료 구독 45명, 월 매출 120만원", "B2B 계약 2곳"
- 15: 돈은 아직이지만 강한 시장 신호가 있다. 예: "대기자 명단 800명", "기업 파일럿 1곳 진행 중"
- 10: 타깃 고객과 수익 모델이 구체적으로 적혀 있다. 예: "1인 카페 사장님 대상, 월 9,900원 구독 예정"
- 5: "누구나 쓸 수 있다"처럼 고객이 막연하다.
- 0: 시장·고객 이야기가 없다.

## 디자인
- 20: 프로필·화면 모두 정보 위계가 분명하고 여백·정렬·글꼴이 일관된다. 첫 화면에서 무엇을 하는 서비스인지 3초 안에 보인다.
- 15: 깔끔하지만 한두 군데 정렬·간격이 어긋나거나 강조가 약하다.
- 10: 기본 템플릿 느낌이 강하거나 정보가 빽빽해 핵심을 찾기 어렵다.
- 5: 글꼴·색이 제각각이고 정렬이 깨져 읽기 힘들다.
- 0: 볼 수 있는 화면·문서가 없다 (판단 불가도 0, 그 사실을 약점에 쓴다).

## 혁신성
- 20: 문제 정의나 해법이 새롭다. 예: "AI 에이전트가 사용자 대신 공공 민원 서류를 채워 제출, 기존엔 사람이 직접"
- 15: 기존 해법을 새 사용자층·새 방식으로 바꿨다. 예: "음성만으로 쓰는 노인용 가계부"
- 10: 흔한 아이디어를 조금 개선했다.
- 5: 이미 많이 있는 것과 거의 같다.
- 0: 새로움에 대한 근거가 없다.
